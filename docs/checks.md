# What it checks

OWASP is a non-profit foundation dedicated to improving software security. Using data from thousands of real applications, it publishes the most common risks. Its "Top 10" list is the most widely used reference for talking about application security; the latest edition is the 2025 one.

Findings are classified with the OWASP Top 10:2025 categories. Covering a category does not mean there are no other risks.

> Covering Top 10 categories does not mean other risks do not exist. Heimdall Guardian reads the code without running it: it does not replace a human review or penetration testing.

| Category | Coverage | What it is | Example | What Heimdall does |
|---|---|---|---|---|
| A01:2025 Broken Access Control | Yes | Someone can see or do something they are not allowed to. It also includes the system making requests to addresses chosen by an attacker. | Someone changes a number in the web address and sees another person's data. | Inventory of endpoints without authentication, rules for access to other people's objects, file paths, redirects and requests to user-chosen addresses. The AI endpoint review only suggests. |
| A02:2025 Security Misconfiguration | Yes | The system is left with factory or development settings that expose it. | A production application is still in test mode and shows its internal errors. | Configuration rules (debug mode, CORS, cookies, visible errors) and a review of configuration files and infrastructure as code. |
| A03:2025 Software Supply Chain Failures | Partly | Third-party components with known flaws are used, or the way the software is built and delivered is compromised. | The application uses a library with a public flaw that already has a fix. | Dependencies with known vulnerabilities and a component inventory (SBOM). It does not check the integrity of the build or publishing process. |
| A04:2025 Cryptographic Failures | Partly | Sensitive data is poorly protected or not protected at all: weak encryption, visible keys or carelessly stored passwords. | Users' passwords are stored with a method that can be cracked in minutes. | Weak cryptography, predictable randomness and secrets written in the code. It does not check encryption in transit or at rest in the infrastructure. |
| A05:2025 Injection | Yes | Data typed by the user is interpreted as an instruction and the system runs it. It includes SQL, command and in-page code (XSS) injection. | Someone types an instruction in a search field and gets the whole database. | Rules for SQL, NoSQL, command, code and in-page script (XSS) injection for the supported languages. |
| A06:2025 Insecure Design | Partly | The problem is not a programming mistake but how the system was conceived: controls are missing from the design. | A process lets a discount coupon be reused without limit because nobody foresaw the abuse. | Only AI suggestions about business flows and a few design rules (file upload, mass assignment). Design needs a human review. |
| A07:2025 Authentication Failures | Partly | The system does not properly check who each person is, or lets someone pretend to be another person. | An access key was left in the code and anyone with the file can get in. | Exposed secrets, poorly verified JWT tokens, and insecure sessions and cookies. It does not test weak passwords or two-factor authentication. |
| A08:2025 Software or Data Integrity Failures | Partly | The system trusts code or data that nobody verified and that could have been tampered with. | The application rebuilds objects from received data and an attacker manipulates them. | Insecure deserialization of external data. It does not check update signatures or delivery channels. |
| A09:2025 Security Logging and Alerting Failures | No | Important events are not recorded, or nobody finds out about an attack in time. | Someone tries thousands of passwords for a week and nobody gets a warning. | A code analysis cannot know whether monitoring and alerts are in place in production. |
| A10:2025 Mishandling of Exceptional Conditions | No | The system reacts badly to errors or unexpected situations: it crashes, opens up or reveals information. | On an error, the system lets the operation through instead of blocking it. | Heimdall Guardian has no rules for this category: a code analysis cannot see how the system reacts to failures in production. |
