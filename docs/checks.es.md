# Qué revisa

OWASP es una fundación sin fines de lucro dedicada a mejorar la seguridad del software. Con datos de miles de aplicaciones reales publica cuáles son los riesgos más comunes. Su lista «Top 10» es la referencia más usada en el mundo para hablar de seguridad de aplicaciones; la edición más reciente es la de 2025.

Los hallazgos se clasifican con las categorías del OWASP Top 10:2025. Cubrir una categoría no significa que no existan otros riesgos.

> Cubrir categorías del Top 10 no significa que no existan otros riesgos. Heimdall Guardian lee el código sin ejecutarlo: no sustituye una revisión humana ni las pruebas de penetración.

| Categoría | Cobertura | Qué es | Ejemplo | Qué hace Heimdall |
|---|---|---|---|---|
| A01:2025 Control de acceso roto | Sí | Alguien puede ver o hacer algo que no le corresponde. También incluye que el sistema haga peticiones a direcciones que elige un atacante. | Alguien cambia un número en la dirección web y ve los datos de otra persona. | Inventario de endpoints sin autenticación, reglas de acceso a objetos ajenos, rutas de archivo, redirecciones y peticiones a direcciones elegidas por el usuario. La revisión de endpoints con IA solo sugiere. |
| A02:2025 Configuración de seguridad incorrecta | Sí | El sistema queda con ajustes de fábrica o de desarrollo que lo dejan expuesto. | Una aplicación en producción sigue en modo de pruebas y muestra sus errores internos. | Reglas de configuración (modo de depuración, CORS, cookies, errores visibles) y revisión de archivos de configuración e infraestructura como código. |
| A03:2025 Fallas en la cadena de suministro de software | En parte | Se usan componentes de terceros con fallas conocidas, o se compromete la forma en que el software se construye y se entrega. | La aplicación usa una librería con una falla pública que ya tiene arreglo. | Dependencias con vulnerabilidades conocidas e inventario de componentes (SBOM). No revisa la integridad del proceso de compilación ni de publicación. |
| A04:2025 Fallas criptográficas | En parte | Los datos sensibles se protegen mal o no se protegen: cifrado débil, claves visibles o contraseñas guardadas sin cuidado. | Las contraseñas de los usuarios se guardan con un método que se descifra en minutos. | Criptografía débil, aleatoriedad predecible y secretos escritos en el código. No revisa el cifrado en tránsito ni en reposo de la infraestructura. |
| A05:2025 Inyección | Sí | Un dato que escribe el usuario se interpreta como una instrucción y el sistema la ejecuta. Incluye las inyecciones de SQL, de comandos y de código en páginas (XSS). | Alguien escribe una instrucción en un campo de búsqueda y obtiene toda la base de datos. | Reglas de inyección SQL, NoSQL, de comandos, de código y de scripts en páginas (XSS) para los lenguajes soportados. |
| A06:2025 Diseño inseguro | En parte | El problema no está en un error de programación sino en cómo se pensó el sistema: faltan controles desde el diseño. | Un trámite permite repetir un cupón de descuento sin límite porque nadie previó el abuso. | Solo sugerencias de la IA sobre flujos de negocio y algunas reglas de diseño (carga de archivos, asignación masiva). El diseño requiere revisión humana. |
| A07:2025 Fallas de autenticación | En parte | El sistema no comprueba bien quién es cada persona, o permite que alguien se haga pasar por otra. | Una clave de acceso quedó escrita en el código y cualquiera con el archivo entra. | Secretos expuestos, tokens JWT mal verificados, sesiones y cookies inseguras. No prueba contraseñas débiles ni segundo factor de autenticación. |
| A08:2025 Fallas de integridad de software o datos | En parte | El sistema confía en código o datos que nadie verificó y que pudieron alterarse. | La aplicación reconstruye objetos a partir de datos recibidos y un atacante los manipula. | Deserialización insegura de datos externos. No revisa firmas de actualizaciones ni canales de entrega. |
| A09:2025 Fallas de registro y alertas de seguridad | No | Los eventos importantes no se registran o nadie se entera a tiempo de un ataque. | Alguien prueba miles de contraseñas durante una semana y nadie recibe un aviso. | Un análisis del código no puede saber si hay vigilancia y alertas en operación. |
| A10:2025 Manejo inadecuado de condiciones excepcionales | No | El sistema reacciona mal ante errores o situaciones inesperadas: se cae, se abre o revela información. | Ante un error, el sistema deja pasar la operación en lugar de bloquearla. | Heimdall Guardian no tiene reglas para esta categoría: un análisis del código no ve cómo reacciona el sistema ante fallas en operación. |
